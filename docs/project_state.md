## 2. Database Schema Snapshot

### Tables:
- `users`: Standard authentication table (`id`, `name`, `email`, `status` (active/suspended, indexed), `email_verified_at`, `password`, `remember_token`, `profile_photo_path`, `photo_hash`, `timestamps`).
- `employees`: Reference staff table (`id`, `user_id` (nullable FK to users), `full_name`, `registration_number` (unique), `position`, `status` (active/inactive/on_leave, indexed), `join_date`, `salary` (decimal 12,2), `daily_rate` (decimal 10,2), `address`, `profile_photo_path`, `photo_hash`, `timestamps`, `deleted_at` (soft deletes)).
- `password_reset_tokens`: Password reset handling (`email`, `token`, `created_at`).
- `sessions`: Database session driver table.
- `cache` & `cache_locks`: Database cache storage.
- `jobs`, `job_batches`, `failed_jobs`: Database queue driver tables.
- AI certificate extraction defaults to Laravel's `database` queue connection via `GEMINI_QUEUE_CONNECTION`; a running queue worker is required to process extraction jobs. Gemini calls have a 25-second total deadline via `GEMINI_MAX_DURATION`.
- `roles`, `permissions`, `model_has_roles`, `model_has_permissions`, `role_has_permissions`: Spatie RBAC tables. Configured roles: `Super-Admin` (protected super role), `User` (protected baseline default role, auto-assigned to new registrants), `Admin`, `manager`.
- Extraction records persist the active Gemini key number (`ai_key_index`) and current model for safe operational visibility without exposing API secrets.
- `activity_log`: Spatie audit trail and event logging table.
- `notifications`: Laravel database notifications table (`id (uuid)`, `type`, `notifiable_type`, `notifiable_id`, `data (json)`, `read_at`, `timestamps`).
- `system_settings`: Key-value configuration table with JSON casting and caching (`id`, `key`, `value`, `group`, `description`, `timestamps`).
- `grandeurs`: Metrological physical quantities and measurement standards (`id`, `name`, `symbol`, `type` (measurement/source, indexed), `timestamps`).
- `equipment`: Metrology and field equipment catalog (`id`, `internal_code`, `full_name`, `short_name`, `serial_number` (unique), `category` (indexed), `package` (indexed), `requires_calibration` (boolean, indexed), `designation`, `status` (indexed), `image_path`, `image_hash` (indexed), `certificate_path`, `notes`, `timestamps`, `deleted_at` (soft deletes)). Domain-scoped by `scopeForCalibration()` and `isCalibrationEligible()` ensuring strict isolation from vehicles and work tools.
- `equipment_specifications`: Technical ranges and precision tolerances per equipment and physical quantity (`id`, `equipment_id` (FK cascade), `grandeur_id` (FK cascade), `range_min`, `range_max`, `accuracy_value`, `accuracy_type` (% / abs), `timestamps`).
- `instruments`: Industrial measuring instruments catalog (`id`, `site_id` (FK to sites), `tag_number` (indexed), `serial_number` (unique), `instrument_type` (indexed), `process_variable` (indexed), `measurement_type`, `fluid_type`, `technology`, `image_path`, `image_hash` (indexed), `status` (indexed), `timestamps`, `deleted_at`).
- `instrument_specifications`: Metrological measurement ranges and precision limits per instrument and quantity (`id`, `instrument_id` (FK cascade), `grandeur_id` (FK cascade), `range_min`, `range_max`, `accuracy_value`, `accuracy_type`, `timestamps`).
- `flow_computer_transmitter`: Multi-channel mapping between Flow Computers and Transmitters (`id`, `flow_computer_id` (FK cascade), `transmitter_id` (FK cascade), `channel_number` (string 50, supporting alphanumeric codes like CH1/AI-01), `timestamps`).
- `flow_computer_verifications`: ADC verification sessions per flow computer channel (`id`, `report_mission_id` (FK), `instrument_id` (FK), `simulated_transmitter_id` (FK), `shunt_resistance`, `verification_date`, `overall_status`, `timestamps`).
- `flow_computer_verification_points`: Calibration measurement points for flow computer ADC verifications (`id`, `verification_id` (FK cascade), `step_order`, `cycle_phase`, `applied_percentage`, `expected_signal`, `measured_signal`, `calibrator_1_correction`, `corrected_signal`, `expected_value`, `calibrator_2_correction`, `corrected_expected_value`, `indicated_value`, `absolute_error`, `emt_limit`, `is_conforme`, `timestamps`).
- `standard_gauge_specifications`: Metrological standards specifications for capacity gauges (`id`, `instrument_id` (FK cascade unique), `nominal_capacity_liters`, `neck_scale_sensitivity`, `cubical_expansion_coef_gcm`, `vessel_material`, `base_reference_temperature`, `calibration_certificate_number`, `calibration_date`, `calibration_expiry_date`, `timestamps`).
- `prover_specifications`: Mechanical and displacement specifications for pipe / SVP provers (`id`, `instrument_id` (FK cascade unique), `type`, `inner_diameter`, `wall_thickness`, `nominal_base_volume`, `cubical_expansion_coef` ($G_c$), `area_expansion_coef` ($G_a$), `linear_expansion_coef` ($G_l$), `elasticity_modulus` ($E$), `material`, `pulse_interpolation`, `timestamps`).
- `contracts`: Commercial customer contracts table (`id`, `reference` (unique), `customer_id` (FK to customers), `garantie_id` (nullable FK to `garanties` nullOnDelete), `object`, `date_signature`, `duree` (months), `date_fin`, `montant_global_prevu`, `status`, `timestamps`).
- `contract_items`: Central bridge table connecting contracts to article/item types (`id`, `contract_id` (FK cascade to `contracts`), `item_type_id` (FK to `item_types`), `designation`, `quantity`, `unit_price`, `type`, `unit_cost`, `frequency` (`BillingCycle`), `timestamps`).
- `item_types`: Master article / item types classification catalogue (`id`, `designation` (unique), `timestamps`).
- `attachments`: Monthly/periodic billing attachments linked to contracts (`id`, `contract_id` (FK cascade to `contracts`), `reference`, `period_start`, `period_end`, `status`, `total_amount`, `timestamps`).
- `attachment_items`: Quantity consumption tracking per contract item (`id`, `attachment_id` (FK cascade to `attachments`), `contract_item_id` (FK cascade to `contract_items`), `actual_quantity`, `unit_price`, `total`, `timestamps`).
- `missions`: Field operations missions (`id`, `reference` (unique), `site_id` (FK to sites), `team_leader_id` (FK to employees), `status` (`MissionStatus`), `start_date`, `end_date`, `description`, `timestamps`, `deleted_at` (soft deletes)).
- `mission_orders`: Individual employee travel orders within missions (`id`, `mission_id` (FK cascade to `missions`), `employee_id` (FK to employees), `equipment_id` (nullable FK to equipments), `status` (`MissionOrderStatus`), `transport_mode`, `per_diem_rate`, `departure_date`, `return_date`, `timestamps`).
- `mission_deployments`: Calibrator & equipment deployment logistics per mission (`id`, `mission_id` (FK cascade to `missions`), `equipment_id` (FK to equipments), `status` (`MissionDeploymentStatus`), `dispatched_at`, `returned_at`, `timestamps`).
- `calibration_certificate_extractions`: AI-assisted Gemini calibration certificate extraction jobs (`id`, `certificate_path`, `status` (`ExtractionStatus`), `ai_key_index`, `model_name`, `extracted_data` (json), `error_message`, `timestamps`).
- `calibration_interpolations`: Florian Platel linear interpolation 5-point grid calculations (`id`, `equipment_specification_id` (FK cascade), `x_point`, `y_interpolated`, `uncertainty`, `lower_limit`, `upper_limit`, `timestamps`).
- `charges`: Financial expenses and operational charges (`id`, `amount` (decimal 12,2), `date` (date), `type` (`ExpenseAffiliation`: mission, contract, item, gmtm, prisma), `charge_type` (`ExpenseChargeType`: fixed, variable, nullable), `description` (string), `mission_id` (nullable FK cascade), `contract_id` (nullable FK cascade), `attachment_item_id` (nullable FK cascade), `item_type_id` (nullable FK cascade), `notes` (text, nullable), `timestamps`).

## 8. Standing Architectural Directives & Conventions

- **Clean Architecture & Domain Decoupling:**
  - Controllers are ultra-thin: only accept validated FormRequests, delegate execution to Services/Repositories, and return views or redirects with standard flash keys (`with('success')`, `with('error')`, `with('warning')`, `with('info')`). Zero Eloquent queries or transactions in controllers.
  - Repositories (`app/Repositories/` implementing `app/Interfaces/`) encapsulate all data queries, eager loading (`with()`), and dynamic filtering (`FilterableTrait`) to eliminate N+1 bottlenecks.
  - Domain Services (`app/Services/`) manage business logic, arithmetic computations, atomic database transactions (`DB::transaction`), and media pipeline processing.
  - Dedicated FormRequests (`app/Http/Requests/`) are required for all mutative requests (`Store...Request`, `Update...Request`).
- **Design System, UI Tokens & Component Suite:**
  - Authoritative UI standards are centralized in [AGENTS.md](file:///c:/Project%20HARD/erp.gmtm-dz.com/AGENTS.md), `resources/css/tokens.css`, and core Blade components.
  - Standard buttons only: `<x-primary-button>`, `<x-secondary-button>`, `<x-danger-button>`, `<x-success-button>`, `<x-warning-button>`, `<x-info-button>`.
  - Standard table suite only: `<x-table>`, `<x-table.th>`, `<x-table.tr>`, `<x-table.td>`, `<x-table.actions>`, `<x-table.action>` (polymorphic base supporting `view`, `edit`, `delete`, `download`, `restore`, `pdf`, `excel`/`csv`, `print`, `stats`/`chart`, `primary`, `success`), and dedicated semantic wrapper components (`<x-table.action-view>`, `<x-table.action-edit>`, `<x-table.action-delete>`, `<x-table.action-pdf>`, `<x-table.action-excel>`, `<x-table.action-print>`, `<x-table.action-stats>`).
  - Standard filter: `<x-global-filter>` with permanent query string persistence (`->withQueryString()`, `$request->query()`).
  - Standard badges: `<x-badge :variant="...">` using 3 functional tiers (Management: `primary`, Engineering: `info`, Technicians: `neutral`). Status indicators use status dots (`:dot="true"`). PHP Enums implement `badgeVariant(): string`.
  - Zero inline styles (`style="..."` prohibited) and fluid full-width layout (`w-full px-4 sm:px-6 lg:px-8`).
- **Trilingual Localization Parity (100% English Master Keys):**
  - Canonical master keys in code (`__('...')`) MUST be in English. Arabic and French text exist exclusively as translated values in `lang/ar.json` and `lang/fr.json`. Exact 1-to-1 key parity is maintained (currently 2,787 keys).
- **Static Code-First RBAC Architecture:**
  - Permissions are statically declared in `config/permissions.php` under `$groups` and synchronized via `php artisan permissions:sync-tables`.
  - Super role bypass (`Super-Admin`) is declared in `AppServiceProvider`. Anti-self-action policy strictly blocks self-demotion, self-suspension, or self-deletion.
- **Media Optimization & CAS Engine (`MediaOptimizationService`):**
  - All uploaded media must transit through `MediaOptimizationService` for compulsory WebP conversion (80% quality, max 1920px), SHA-256 CAS deduplication, and "Process & Destroy" temporary file unlinking.
- **Security Quarantine:**
  - System Administration (`resources/views/system/**`, `system-tables.*`) is quarantined behind `Super-Admin` role exclusivity and requires explicit developer verification.
- **Living Memory, Documentation-First & Active Contracts Directives:**
  - **Mandatory Documentation-First Discovery (حظر مسح الكود العشوائي واستعمال التوثيق أولاً):**
    The AI assistant is **strictly prohibited** from performing blind codebase scans or reading numerous PHP/Blade code files to discover schemas, models, relations, or routes. `docs/project_state.md` and domain documentation (`docs/* Code Details.md`) are the authoritative Single Source of Truth.
  - **Living Domain Relationship (ربط العقود بأصناف الأغراض):**
    `ContractItem` (`contract_items`) is the single entity connecting Contracts (`contracts`) with the master catalogue of article/item types (`item_types`).
  - **Active Contracts Selection Filter Invariant (حصر اختيار العقود في العقود النشطة فقط):**
    Contracts dropdowns and selection lists across all operations views/forms must strictly filter for **active contracts only** (`scopeActive()` / `whereDate('date_fin', '>=', now())`); expired or terminated contracts must never appear in selection lists.
  - **Mandatory Documentation Update Protocol (إلزامية التحديث الفوري للوثائق المساعدة):**
    A task is NOT complete until supporting documentation is synchronized. Whenever any model, relation, route, or feature is created or changed, `docs/project_state.md` and `docs/changelog.md` MUST be updated immediately before concluding the turn.
